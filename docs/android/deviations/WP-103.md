# WP-103 native parser adaptations

Source: `db14559b39d32322b06477c6ae676112f583db50`.
Only the leased parser production/tests and WP-103 evidence/deviation paths change.
The original Swift, resources, licenses, manifest, policy, workflows, dependency
catalogs/locks and shared model/event/LPP contracts remain read-only.

## Wire and consumer behavior

The stateless router covers all **46 actual response codes**, including every
response/push leaf and unknown-code failures. It consumes the existing **53-case
MeshEvent** vocabulary, canonical `Bytes`/checked `ByteReader`/`ByteWriter`,
`model.AutoAddConfig`, LPP types and `event.RxLogTypes`. No competing DTOs, placeholder
events, cached radio capabilities or physical connection are introduced.
Status layout, binary-response public-key prefix/tag and neighbour prefix length
remain explicit caller/request context. Generic binary responses retain their tag
and uninterpreted body; the source discards the request-type byte. Session-owned
correlation and event assembly remain WP-107.

Mandatory fields use checked reads after the original guards. Leaf failures contain
the original **payload** and source reason; unknown/empty router failures retain the
whole frame. Stats leaf failures strip both the response and stats-type bytes.
Source validation order is retained, including reserved contact-path detection
before other complete-contact parsing and the source's misleading
`NewAdvertisement ... insufficient contact data: 147 < 147` reason for a complete
contact with reserved path encoding.

Optional fields and permissive behavior are not silently tightened:

| Source behavior | Native behavior and evidence |
| --- | --- |
| Pre-v3 device defaults; v9/v10 missing extension bytes | Same defaults; no inference from a cached firmware version |
| ACK trip time, packet receive errors and binary-status trailers | Read only complete fields; partial trailers remain ignored where the source ignores them |
| A 58-byte status push calls the source's zero-on-short UInt32 helper at offset55 | Deliberately invokes that canonical helper for this one source-specific read; the checked reader never manufactures zero. Independent 58-byte/partial/full room and repeater vectors execute |
| Short login payload yields non-admin, zero-permission `LoginInfo` | Same original safe fallback, explicitly logged; it is not a newly invented successful login |
| Short neighbour header yields zero/empty response | Source-compatible `parse` logs it; `decode` retains the full input plus a typed truncation diagnostic, and `requireComplete` fails |
| ACL/MMA stop at malformed suffix; neighbours return complete available rows | Source prefix preserved; additional diagnostic APIs retain unconsumed bytes/offsets. Strict access throws `BinaryParseException` rather than claiming complete decoding |
| Negative signed neighbour results count traps in Swift's `0..<resultsCount` | Typed `NegativeResultsCount` failure instead of a process trap. Signed total count and signed Int32 seconds-ago remain unchanged |
| Public neighbour parser accepts Int, but its session caller supplies UInt8 | Native accepts 0..255 (including zero); values outside that actual request contract throw typed `InvalidInput` |
| Channel datagram declared length is clamped; extra suffix ignored | Same binary-byte policy, including null/high-bit bytes; no text decoding |
| Contact path uses fixed64-byte field and `prefix(actualPathLen)` | Same encoded byte, flood sentinel and prefix clamp even if encoded length exceeds64; unknown contact type retains its raw byte alongside `.CHAT` fallback |
| Reserved path encoding accepted diagnostically in path discovery, but rejected in contacts/advert-path/RF | Source-specific rules retained, not unified into a speculative firmware rule |
| Trace uses 1/2/4/8-byte hashes, unlike normal path's 1/2/3-byte hashes | Same flags, integer-division hop count, destination marker and separate final signed SNR |
| MMA current is unsigned; colour/GPS use first signed Int16 /100 | These surprising source behaviors remain, distinct from normal LPP. All27 sensor types have independent arithmetic/BE vectors |

Telemetry returns the real `TelemetryResponse`. Its canonical `decodeResult`
preserves accepted LPP points, malformed suffix diagnosis and raw remaining bytes.
No replacement "empty telemetry" result is returned.

## JVM adaptations

`java.time.Instant` carries Unix seconds without a milliseconds/2001-epoch change.
The source's missing contact-end timestamp samples the wall clock; a caller-supplied
`Clock` makes that one fallback deterministic without introducing session state.

Text follows each original policy: exact UTF-8 with the existing empty-string
fallback for self/device/custom-vars fields; first-null and longest-valid-prefix
decoding for contacts; first-null/lossy decoding for channel/scope names; lossy,
untrimmed message text; strict typed failure for region responses. Lossy decoding
implements Unicode maximal subparts because the JDK replacement decoder collapses
UTF-8 surrogate bytes differently from Swift. Python's independent decoder verifies
all256 single bytes, overlong/surrogate/truncated sequences and representative
emoji/ZWJ/combining/CJK/RTL/null text. Foundation's documented control/format and
whitespace/newline categories are handled by code point, including supplementary
format controls. No app formatting/localized recovery is copied into the MIT module.

Scope derivation reuses the actual model SHA-256 helper. After the coordinator's
verified WP-102 merge, this branch was reconciled onto
`79bd7790edb174ed702010b98ee09b2674b70a3e` and transport-code calculation now
reuses the real public `WireCrypto.hmacSha256` rather than duplicating
JCA/empty-key handling. It preserves low-nibble input, checked little-endian
first-two-byte extraction and reserved0/65535 rewrites. The merged helper uses
vetted JCA HMAC, RFC2104 normalization for empty keys and typed provider failures.
All82 independent HMAC vectors, including actual reserved-boundary MACs and
empty/long keys, execute unchanged. No parser dependency/catalog/lock/provider
change was made; WP-102 owns its independently admitted BC dependency/notices.
Android device/provider execution is not claimed.

Ambiguous names remain deduplicated and sorted, with no first-hit shortcut.
Canonical-equivalent names deduplicate as Swift strings do. Foundation's
`localizedStandardCompare` is adapted to a caller-testable JVM locale collator with
numeric runs, canonical decomposition and a deterministic tie-break. This is
presentation ordering, not a change to scope-key/HMAC bytes. Exact Finder collation
for arbitrary locales is **not** claimed; the native adaptation is exposed for
review, and original ASCII ambiguity cases plus numeric ordering execute.
