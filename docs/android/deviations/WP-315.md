# WP-315 line-of-sight logic layer: adaptations and deferrals

Reference: `db14559b39d32322b06477c6ae676112f583db50`. External contribution, no
lease. Acceptance IDs: `WP-315-behavior`, `WP-315-boundaries`,
`WP-315-source-test-parity`. Scope is the **logic layer only**; there are no
Compose screens, no map engine and no app wiring in this change. This document
is not a parity verdict or merge approval.

## Module boundary and type placement

feature modules may depend only on `core:model`, `core:contracts`,
`core:designsystem`, `core:ui`, `core:maps`, `core:l10n` (`ModuleGraph.kt`), so
the WP-212 RFCalculator and WP-218 ElevationService in `core:services` are not
reachable. Decisions:

1. **Ports (preferred).** Everything the view model only *calls* goes through
   feature-owned interfaces in `LineOfSightPorts.kt`:
   `LineOfSightElevationSource` (WP-218 `fetchElevation`/`fetchElevations`
   plus the `optimalSampleCount`/`sampleCoordinates` statics),
   `LineOfSightPathAnalyzer` (WP-212 `distance`, `analyzePath`,
   `analyzePathSegment`), `LineOfSightContactSource` (the one
   `fetchContacts(radioId)` read, with an adapter from `ContactPersisting`) and
   `LineOfSightFailureReporter` (replaces the source's `os.Logger` error logs).
   App wiring must adapt the core:services implementations onto them.
2. **Value-shape mirrors.** `ElevationSample`, `ClearanceStatus`,
   `ObstructionPoint`, `PathAnalysisResult` (fields, `distanceKm`,
   `worstObstructionPoint`), `SegmentAnalysisResult` and
   `RelayPathAnalysisResult` are feature-local mirrors of the WP-212 types
   (`LineOfSightRfValues.kt`, Swift IEEE equality, ids ignored).
   `peakObstructionPerRegion` is not mirrored; only the deferred map pins use it.
   The adapter maps WP-212 results field by field.
3. **Duplicated pure math.** `LosFresnelMath` mirrors only `wavelength`,
   `fresnelRadius` and `earthBulge`, because the WP-315-owned
   `FresnelZoneRenderer` calls them directly and its source tests pin their
   values. Same constants and operand order; no `log10`, so WP-212's
   correctly rounded log is not needed. If a shared RF module is admitted
   later, this file and the mirrors should be deleted in favor of it.

## Native adaptations

- **State holder.** A plain class with `StateFlow<LineOfSightState>`, an
  injected single-threaded `CoroutineScope` (stands in for `@MainActor`) and an
  injected `analysisContext` for the source's `Task.detached` analysis. There is
  no androidx `ViewModel` and no clock: the source logic has no time-based
  behavior. Tests drive fake fetch delays with a virtual clock. Swift `didSet`
  side effects become explicit setters (`setRefractionK` re-analyzes,
  `setRepeaterPoint`, `setRelocatingPoint`). `dispose()` replaces the isolated
  `deinit`.
- **Cancellation.** A superseded or cancelled task never publishes results or
  errors. `CancellationException` is always rethrown. One Kotlin difference:
  a job cancelled *before its first dispatch* does not run its body, while a
  Swift `Task` still runs and then checks `isCancelled`. Every cancelling path
  sets `isAnalyzing` itself, so the visible state is the same.
- **Error text.** `AnalysisStatus.Error` carries the failure's
  `localizedMessage` in place of `localizedDescription`. Adapters supply the
  user-facing (WP-005/WP-218 localized) message.
- **"Dropped pin".** `SelectedPoint.displayName(droppedPinLabel)` takes the
  resolved text of `SelectedPoint.DROPPED_PIN_LABEL`
  (`AppToolsStrings.toolsLineOfSightDroppedPin`). A logic-layer unit test
  cannot resolve resources.
- **Numerics.** Swift `min`/`max`/`clamped` semantics (NaN, signed zero) are
  reproduced. Foundation `fractionLength` formatting is ICU-equivalent:
  half-even on the shortest decimal, grouping, and a kept minus sign for
  values that round to zero. `"%.1f"` uses the exact binary value, half-even.
  Frequency parsing follows the Swift `Double(String)` grammar: no whitespace,
  hex floats and `inf`, no `f`/`d` suffixes. All of this is pinned to the
  swiftc oracle. Residual risk: on Android runtimes older than the JDK 19
  shortest-repr algorithm, a rare `Double.toString` can be non-shortest. Swift
  `Int(_:)` traps on NaN or out-of-range input; Kotlin conversions saturate
  instead of crashing.
- **Locale.** Formatting functions take an explicit `Locale` instead of the
  implicit current locale.

## Deferred (not ported, not faked)

- **Map engine and picking (needs WP-302 `core:maps`, MapLibre admission).**
  `mapPoints`/`mapLines` (pin styles, clustering, obstruction pins via
  `peakObstructionPerRegion`, line opacities while relocating), `showLabels`,
  stable map IDs, `cameraRegion`/`cameraRegionVersion`/`setCameraRegion`/
  bounding-region fitting, live user-location centering and map gesture to
  coordinate conversion. The holder exposes the coordinates instead:
  `repeaterCoordinates` and the A/B list from `onAnalysisStatusChanged()`.
- **Compose UI (needs core:ui PR #33).** All layout-only views, sheet detents,
  drag-hint tooltip and its one-time preference, nudge animation timing,
  colors and icons, legend and empty state, copy/share/open-in-maps actions
  (these need `Coordinate.formattedString` and platform intents).
  `LineOfSightLayoutMode` is a layout-only enum.
- **Measurement formatting.** `formatDistance` (road-usage units),
  `formatFrequency` and `formatAssumptions` need the WP-005 localized template
  and Measurement-unit formatting, so they belong to the UI layer.
- **Source test ids.** None of the 103 owned ids are deferred. The Swift
  suites do not exercise the map or layout code.

## Coordinator notes

1. `android/feature/tools/build.gradle.kts` is outside WP-315's write paths.
   Now that feature:tools has unit tests, it needs the scaffold hook used by
   other modules:
   `rootProject.tasks.named("verifyScaffoldTests") { dependsOn(":feature:tools:testDebugUnitTest") }`
   (optionally `tasks.named("check") { dependsOn("testDebugUnitTest") }`).
   `controller/module_junit.py` already treats any module with `src/test` as
   active and will require its JUnit reports.
2. App or integration wiring must adapt WP-212 `RFCalculator` and WP-218
   `ElevationService` (on its `ElevationPathSample` shape) onto the WP-315
   ports and value mirrors, and map `ElevationServiceError` to localized text.
3. The map and Compose layers above must consume
   `LineOfSightState.terrainChartInput`, the
   `TerrainProfileChart` layout and the workflow functions rather than
   re-deriving them. Results are modelled terrain clearance from elevation
   data, never measured reception, and the UI should label them that way.
