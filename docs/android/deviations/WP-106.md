# WP-106 events, payloads and bounded multicast

The native pure-JVM vocabulary preserves all 53 `MeshEvent` cases, their
associated payloads, exact attribute keys/raw values, nullable values and stable
low-cardinality case names at source
`db14559b39d32322b06477c6ae676112f583db50`. It implements the 13 owned event files,
not a pretend parser or connected session.

## Deliberate native contracts

| Source behavior | Native contract |
| --- | --- |
| Swift actor methods perform synchronous registry/broadcast operations | A private monitor serializes these non-suspending operations. Consumers never hold it across a suspension. No thread-affinity or whole-session-operation guarantee is implied. |
| Eager `AsyncStream` subscription before sending a command | `subscribeTracked` registers immediately and returns an ID plus hot, single-consumer `Flow`; collection is not required to start registration |
| Per-subscription `.bufferingNewest(100)` | Each subscriber has its own atomically locked 100-event deque. Overflow removes and reports the actual oldest event. A conflated channel carries wakeups **only**, not payload/ACK data. |
| OS warning/signpost on an actual dropped event | A structured `EventDrop` and injectable observer carry subscription ID, dropped case name and cumulative count. Default JVM logging emits only case/count, never message/key/payload text. |
| Finish drains already buffered events; cancellation unregisters | Explicit finish closes notification and drains the deque; consumer cancellation/early completion synchronously unregisters and discards its pending deque without falsely counting overflow |
| Filter evaluated before buffering | All original factories/prefix/code tests and short-circuit combinators are preserved. Nonmatching traffic cannot evict a buffered ACK. |
| Swift values do not retain mutable caller arrays/dictionaries | Immutable bytes and `EventList`/`EventMap` snapshots prevent mutation through constructor inputs, collection entries or generated copies |
| Swift floating equality | All 14 payload shapes containing `Double` preserve signed-zero equality/hash agreement and NaN inequality rather than boxed JVM `Double.equals` |
| LPP telemetry returns a parsed prefix | `TelemetryResponse` exposes the same prefix and its actual `LPPDecodeResult`, retaining malformed-suffix diagnostics and unconsumed bytes; an empty list is not presented as successful malformed telemetry |
| Swift `Int` is 64-bit | Counts, attempts, RSSI and neighbour ages use `Long`; actual wire `UInt8/16/32` fields retain unsigned types |

A subscription permits one collector, explicitly rather than accidentally
distributing events across multiple collectors of `receiveAsFlow`. Use a new
subscription for each listener. This matches the intended source session
consumers; WP-107 owns waiter-before-send registration and timeout/send-failure
cleanup through the tracked ID.

The dispatcher does not upgrade the source's intentionally bounded broadcast
to an unbounded or conflated data stream. It also does not extend bounded
display/drop behavior to TCP raw input. Whole firmware-exchange serialization,
late-response generation checks, radio teardown and delivery guarantees remain
the actual session/transport WPs.

## Vocabulary prerequisite fragments

The canonical `model.AutoAddConfig` from the merged command foundation is
reused, not duplicated. The actual `Protocol/RxLogTypes.swift` value/enum
definitions are brought forward into the event package because the real
`MeshEvent.rxLogData` payload requires them before WP-103's parser can compile.
All raw nibbles, transport flags, path nodes and the SHA-256 packet-hash prefix
remain present. No RF parser is stubbed and its source ownership is unchanged.

The previously deferred `SessionConfiguration.MessageResult` now contains the
four real message/datagram payload variants. It lives with the event values,
not fabricated placeholder classes in the configuration package. Neighbour
pagination preserves first-page identity, latest reported total, row order,
empty-page termination, UInt16-saturating offsets and the 512-page cap; the
one-second inter-page pause remains the caller's responsibility.

## Original scenarios requiring the remaining session/parser

The five original event-test files contain 17 declarations, including a
six-row firmware-code parameter family. Their direct drop/filter/error
behaviors are exercised, including every factory and each of the six values.
The two `MeshCoreSession.events(filter:)` scenarios execute directly against
the real dispatcher here; their original session-wrapper integration remains
for WP-107. The `PacketParser` error-routing scenario remains for WP-103.
None is represented by an ignored or fake passing session/parser test.

The public event/payload/dispatcher contract is usable and tested, while final
`WP-106-source-test-parity` includes those three cross-component follow-ups.
Existing MIT MeshCore provenance/notices remain unchanged. No new dependency,
Android API, controller policy/owner change, formal self-review, radio/device
certification or whole-app acceptance is claimed.
