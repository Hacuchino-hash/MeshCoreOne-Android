Reference: `db14559b39d32322b06477c6ae676112f583db50`. Base: `c8a16529` (origin/main). Branch `wp306-chatlist`.
Owner role: `chats-ui-engineer`. External contribution, no lease. Everything here is a proposed
adaptation for coordinator review; it is not a parity, acceptance or gate approval.

All code is in `android/feature/chats`, package `com.meshcoreone.android.feature.chats.list` (+ `.ui`).
Module edges: the feature convention's `core:contracts`/`core:ui`/`core:l10n` plus `core:model` and
`core:designsystem` (added in `build.gradle.kts`, which also registers `:feature:chats:testDebugUnitTest`

lockfile change. `ChatsEntry.kt` (WP-002 shell) now takes optional parameters; with `dependencies == null`
it renders the unchanged shell, so `:app` compiles unchanged.

## Type placement decisions

- **T-1 `ChatListFeatureDependencies`** (feature-owned, contracts.md pattern). Sub-seams:
  `ChatListDataSource` (the `DataStore` subset ChatViewModel used), `ChatConversationServices`
  (favorite push, channel clear, notification cleanup, room leave, badge), `ChatReactionClassifier`
  (the `ReactionParser` checks used by previews), `ChatListNavigation` (pending contact/channel/room/room-auth
  requests, as `StateFlow`s), `ChatLinkEnvironment` (selected tab, map/contact/channel/hashtag staging and
  lookups for the link router), plus `connectionState`/`currentRadioId` flows, `reloadRequests`
  (servicesVersion/conversationsVersion), `messageEvents`, `clock`, `diagnostics`.
- **T-2 `ChatListEvent`** mirrors the 13 `MessageEvent` cases only to keep
  `shouldRefreshFailedSendIndicators` testable; the adapter maps the real event onto it.
- **T-3 `ChatListStrings`**: channel default name, flood-routing, direct-hops, header-region and
  scoped-default strings are injected so the title/subtitle/filter rules are JVM-testable. `ui/ResourceChatListStrings`
  backs it with `AppChatsStrings`. Tests use deterministic strings, so they prove the *composition* rules, not the
  localized copy.
- **T-4 Local mirrors of types that live in WP-405 / core:services / core:runtime**:
  `MeshCoreLinkParsing` + `MeshCoreLinkParser` (mirror of `MeshCoreURLParser`; WP-405 owns the production
  parser, the app should bind that one through `ChatLinkEnvironment.parser`), `HashtagLinks`
  (`HashtagDeeplinkSupport` + the `HashtagUtilities` name rules), `ContactLinkResult`/`ChannelLinkResult`/`MapLinkResult`,
  `effectiveFloodRegionName` (the displayable outcome of `ChannelFloodScopeResolver` with
  `supportsUnscopedFloodSend=false`), `ConversationActionTimeout` (mirror of `TimeoutError`; the app's error presenter
  should map it to the shared timeout copy), `ChatChannelKey`. The shell's `ContactLinkRequest`/`ChannelLinkRequest`
  lack `regionScope`; the adapter for `stageChannelLink` must carry it (D-5).
- **T-5** `Conversation`/`ChatRoute`/`ChatConversationType` are Kotlin sealed types over `core:model` DTOs.
  `ChatRoute` keeps the Swift equality (kind + conversation id only).

## Adaptations and deviations

- **D-1 Deferred: `ConversationListScrollPerfHarnessTests::hosted list programmatic scroll stays under hitch budget()`**
  measures a hosted UIKit scroll view against a 16 ms frame budget. The Android equivalent needs a device
  (macrobenchmark / frame timing). Not faked. The sibling source-scan case is ported as a source scan of the Compose
  list files (`platform-adaptation`: no `prewarm`, no per-row `LaunchedEffect(conversation...)`, no `DisposableEffect`).
- **D-2 No Compose UI test.** `feature:chats`'s locked test classpath has only JUnit4, `kotlin-test(-junit)`, JUnit
  platform and coroutines-core (`gradle/dependency-locks/feature-chats.lockfile`). A lock amendment would need
  `androidx.compose.ui:ui-test-junit4` (+ `ui-test-manifest`), `org.robolectric:robolectric` (+ `android-all-instrumented`
  as `core:ui` pins) and `org.jetbrains.kotlinx:kotlinx-coroutines-test`, mirroring `core:ui`'s `testImplementation`
  set. Until then the composables are compile- and lint-checked only; all behavior is tested through the state holders.
- **D-3 Foundation string semantics.** `localizedStandardContains` and `localizedCaseInsensitiveCompare == .orderedSame`
  are re-implemented in `ChatTextMatching` with `java.text.Normalizer` + `Locale.ROOT` case folding, not ICU
  collation (`Collator` cannot express "case-insensitive but diacritic-sensitive"). 23 probes were run through
  `swiftc` (`docs/android/evidence/WP-306/oracle/wp306_strings.*`) and are pinned in `ChatTextMatchingTest`. Known
  residual: locale-specific tailoring (e.g. Turkish dotted/dotless i beyond the probed `İ`), and Foundation's
  full-width quirk (`"ａlice"` does not contain `"alice"`) is matched only for the probed cases.
- **D-4 Adaptive layout.** `ChatsAdaptiveLayout` shows list + `detailPane` side by side at >= 600dp (360dp list pane)
  and the list alone otherwise. The shell does not pass `detailPane` today (it owns its own detail), so the shipped
  behavior is the list pane only; WP-307/308 supply the timeline. `selectedRoute` drives the selected-row highlight.
- **D-5 Link parsing** uses `java.net.URI` and `URLDecoder` instead of `URL`/`URLComponents`: a string `URI` rejects
  (e.g. spaces) returns "not a meshcore link" where `URL(string:)` would percent-encode. Decimal-degree check is a
  hand-written equivalent of `^-?\d{1,3}(\.\d+)?$` (no `\d`). `meshcore://` hashtag secrets use SHA-256 of the
  lowercased `#name`, first 16 bytes (same as `ChannelService.hashSecret`).
- **D-6 Cancellation.** `setNotificationLevel`/favorite toggles roll back optimistic state on cancellation and rethrow
  (Swift `catch` swallowed `CancellationError`). `withDeleteTimeout` maps only `TimeoutCancellationException` to
  `ConversationActionTimeout`; other cancellations propagate and still clear the deleting spinner.
- **D-7 Sorting** is stable (`sortedByDescending`); Swift's `sorted` makes no tie guarantee. Rows without a date sort
  last (`Date.distantPast` sentinel).
- **D-8 Row actions** use `core:ui`'s `SwipeActionsContainer` (horizontal drag >= 48dp or the trailing overflow button
  opens a menu; TalkBack custom actions) plus a long-press `DropdownMenu` with the same actions. There is no
  edge-specific swipe reveal or "full swipe favorites" (iOS leading full swipe); that would need a new core:ui
  component. Delete stays disabled unless the radio is READY and no delete is pending, as in the source.
- **D-9 Icons.** `MeshSymbol` has no bell/bell-slash/at/star glyphs. Stand-ins: muted -> `ERROR`, mentions-only ->
  `SIGNAL`, favorite -> `READY`, new-message -> `MESSAGES`; every one carries the real content description
  (`row.muted`, `row.mentionsOnly`, `row.favorite`). Replace when core:designsystem adds the glyphs. Channel avatars
  use globe/hashtag/lock like the source.
- **D-10 Search UI** is a persistent `OutlinedTextField` below the app bar (iOS uses a nav-bar search drawer); the filter
  chips disable while a search is active (as `GlassFilterBar(isSearching:)`).
- **D-11 Not ported here** (outside the owned list): channel options/join/create sheets (the `onNewChannel` callback),
  room authentication sheet (`onRoomAuthenticationRequested` hand-off), the "meshcoreone://mention" scheme, per-row
  coordinator prefetch/prewarm (WP-307/308 own the coordinator).
- **D-12 Lint**: `lintDebug` reports 3 `LocalContextResourcesRead` warnings (same pattern as `core:ui`'s
  `ConversationTimestamp`; needed for formatted resource strings and TalkBack descriptions). No errors.

## What the app layer must wire

1. Implement `ChatListFeatureDependencies` (data source over `OfflineDataStore`, services adapter over
   `channelService`/`contactService`/`roomServerService`/`notificationService`, reaction classifier over `ReactionParser`,
   `connectionState`/`currentRadioId` flows, `reloadRequests` from `servicesVersion`/`conversationsVersion`,
   `messageEvents` mapped to `ChatListEvent`, `ChatListNavigation` over `NavigationCoordinator`'s pending fields,
   `ChatLinkEnvironment` over the coordinator + `persistence` lookups + WP-405's parser).
2. Pass it into `ChatsEntry(dependencies = ...)` with `selectedRoute`/`onOpenChat`/`onClearSelection` bound to the
   coordinator's `chatsSelectedRoute`, `onNewChannel`, `onRoomAuthenticationRequested`, a `failureText` backed by
   `UiErrorMapper` (map `ConversationActionError.*` and `ConversationActionTimeout`), and an `AvatarImageCache`.
3. Route `onOpenChat` to the stack push (< 600dp) or selection (>= 600dp); hide the tab bar on push as the iOS
   `tabBarVisibility` did.
4. Call `ChatLinkRouter.route` from in-chat `OpenURL` handling and `routeExternalOpen` from the activity's VIEW intents.

## Not verifiable without a device

Swipe/drag and long-press behavior, TalkBack reading order/custom actions, the offline announcement, edge-to-edge
insets under the real shell, the 600dp split, avatar decoding, dialog/sheet presentation, IME behavior with the search
field, and list scroll performance. Only compilation, lint and the state-holder logic are exercised.
