## Native adaptations

- **D-1 Feature-owned ports.** `ChannelSetupPort`, `ChannelInfoPort`, `RoomConversationPort`,
  `RoomAuthenticationPort` and `RoomInfoPort` stand in for `appState.connectedDevice`, `channelService`,
  `dataStore`, `RoomServerService` and `NotificationService`. Features may not import `core:services`, so the
  app layer adapts them (same pattern as `ChatListFeatureDependencies`). No app binding is added here: it is
  outside the WP write paths.
- **D-2 State holders instead of SwiftUI `@State`.** Each sheet's logic (secret generation, input caps,
  slot availability, flood-scope-after-join, delete/clear, region discovery outcomes, room load/send/retry,
  event fold with a 50 ms coalesced reload) is a coroutine-free-of-UI state holder with JVM tests.
- **D-3 Rendering seams.** QR image rendering (`QRCodeGenerator`) and the camera scanner
  (`DataScannerViewController`) are platform code with no allowed dependency in this module; the composables take
  `qrContent` / `scanner` slots, and `ScanChannelQrStateHolder` owns scan-result handling and the join. The
  shared node login sheet (remote-nodes feature) is hosted through `authenticationContent`.
- **D-4 Case coverage.** `RoomConversationViewModelOrderingTests` (12), `ChannelInfoRegionQueryTargetsTests` (9) and
  `RegionNameValidatorTests` (12 cases, both parameter families expanded) are bound with `@OriginalCase` to
  `RoomTimelineTest`, `RegionQueryTargetsTest` and `RegionNameValidatorTest`. The validator itself already lives in
  `core:ui`; the chats test pins the behavior the add-region sheet depends on.

- **D-5 Secret size guard.** Join-private rejects a secret that does not parse to exactly 16 bytes with the
  invalid-format error before any radio write; iOS lets `setChannelWithSecret` reject it. The button is already
  disabled for such input, so this only hardens the direct call.

## Not ported / deferred

- Translation chrome, translation sessions and language detection in room rows/actions: WP-406.
- The incoming-avatar flight animation (`IncomingAvatarFlight`) is view-only polish.
- Channel-info region management/discovery-results screens (`RegionManagementView`,
  `RegionDiscoveryResultsView`) are not composed here; the state holder exposes discovery, results and known-region
  mutation, and the sheet offers flood-scope selection over the known regions.
- `ChatsConversationSheets`, `SendDMSheet`, `ShareContactPickerSheet`, `AddContactConfirmationSheet` and the
  `RoomMessageBubble` / `RoomMessageActionsSheet` / `RoomSettings*` / `RoomStatus*` visuals are not ported in this PR;
  action availability, status mapping and info entries are. Room settings/status logic is owned by WP-313.
- Navigation wiring of the sheets into `ChatsEntry` and app binding of the ports are outside the write paths.
- Full-width (fullwidth digit) hex acceptance of Swift `Character.isHexDigit` is not reproduced; the secret field
  accepts ASCII hex digits only.
