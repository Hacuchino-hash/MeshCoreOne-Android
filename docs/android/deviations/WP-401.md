## Android notification model

Swift notification categories map to Android 8+ notification channels. Audible and silent variants are
separate because Android owns sound at the channel level. Message categories use `MessagingStyle` and
long-lived conversation shortcuts; other categories use big text. Lock-screen public versions expose only
the app and generic category text.

The existing onboarding/settings flow remains the sole owner of `POST_NOTIFICATIONS` prompting. The
delivery adapter reports the current authorization state and never launches permission UI. Denial or
platform posting failure is a typed notification result and never blocks mesh messaging.

## Actions and process lifetime

Android direct reply and mark-read actions use an explicit, non-exported broadcast receiver. Only the
inline-reply `PendingIntent` is mutable. Action extras contain typed radio/contact/session/channel/message
identifiers but no title, body or reply text.

A process-owned queue retains at most 32 cold-start actions and retries for 15 seconds while application
and radio-session state becomes ready. Session creation explicitly retriggers draining. Responses keep the
payload's original radio identity; WP-215 therefore rejects stale-radio transmission while mark-read
targets the payload's own persisted rows.

## Verification boundary

Robolectric exercises notification construction and action plumbing on the host JVM. Android instrumented
test sources compile into an APK, but no emulator/device, launcher badge, OEM channel UI, physical radio,
signing or release verification is claimed.
