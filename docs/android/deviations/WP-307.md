# WP-307: chronological chat timeline and screen state

## Native adaptations

- **D-1 Reverse presentation, chronological state.** `ChatTimelineState.messages` and its row model stay
  oldest-to-newest. The Compose surface supplies `rows.asReversed()` to `LazyColumn(reverseLayout = true)`.
  Paging offsets, unread anchors, grouping, event admission, and persisted scroll anchors therefore do not
  inherit reversed indexes.
- **D-2 Feature dependency seam.** `ChatTimelineDependencies` is the feature-owned adapter boundary for
  persistence, retry, drafts, and the process/radio-owned event stream. The screen starts only its collector;
  it never constructs or cancels the radio session. `ChatTimelineRoute` can fill WP-306's existing detail
  pane without adding a feature-to-feature dependency.
- **D-3 Shared rendering boundary.** WP-307 renders safe plain message text, grouping, sender, day/unread
  dividers, and delivery/retry state. Link/inline-image/mention/emoji composition remains WP-308, and
  reactions/details/path/map actions remain WP-309. No second preview, rich-text, send, or WebView pipeline
  is introduced.
- **D-4 Screen restoration.** Drafts persist through the injected conversation-keyed store on every edit.
  Scroll restoration uses stable radio/message identity plus pixel offset. Re-entering a route may refresh
  the database window but cannot submit a message; accepted-send draft clearing remains an explicit call
  from the WP-308 composer.
- **D-5 Initial unread window.** The first fetch expands from 50 rows to unread count plus 12 rows of read
  context, capped at 200. A one-row lookahead proves whether older history exists. The persisted unread
  anchor is used when present; if it falls outside the bounded window, the oldest loaded row is the honest
  fallback rather than withholding the screen indefinitely.
- **D-6 UI verification.** The existing chats module has JVM state tests but no locked Compose UI-test
  dependencies. The Compose route/content compile and pass Android lint; deterministic JVM tests cover the
  reverse-order projection, stable keys, grouping, paging, anchors, event guards, delayed ACKs, retry,
  draft, reconnect refresh, and error-state transitions. Hardware scrolling, TalkBack, IME, and screenshot
  evidence are not claimed.

## Error and lifecycle behavior

Initial-load failures retain a retryable empty state. Paging failures keep the loaded window and expose a
polite live-region retry surface. Cancellation propagates after retiring loading/retry state. Retry admission
is single-flight, and a late failure cannot overwrite a delivered ACK. Recomposition cannot duplicate
event collection or load effects because both are keyed to the retained `ChatViewModel`.
