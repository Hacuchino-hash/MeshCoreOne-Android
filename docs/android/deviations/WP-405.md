# WP-405 deviations

| Area | Adaptation | Observable behavior |
| --- | --- | --- |
| External delivery | Android `ACTION_VIEW` intents are staged in the retained activity `ViewModel` until the process container is available. Delivery IDs prevent activity recreation and repeated readiness signals from routing the same intent twice; cancellation leaves the delivery retryable. | Preserves the frozen `PendingExternalURL` cold-start/once-only contract using Android lifecycle primitives. |
| Confirmation UI | Unknown contacts, channels and hashtags populate the existing typed WP-302 confirmation requests. WP-405 does not add the WP-310 confirmation sheets or perform the requested mutation itself. | External links cannot add contacts/channels, change radio configuration, or execute administrative commands without the separately owned confirmation flow. |
| Internal mention links | Mention URI encoding/decoding is ported for internal navigation parity, but no external manifest filter is registered for it. | Mention links remain app-internal and are not an exported entry point. |
| URI implementation | Kotlin uses `java.net.URI` plus a strict UTF-8 percent decoder. Query parsing preserves first-value-wins behavior and form-query `+` semantics while rejecting malformed escapes and malformed UTF-8. | Matches the frozen encoding, query-injection and malformed-input behavior without relying on Android framework URI decoding. |
| Flood scope | The optional channel region is UTF-8 capped at the shared 30-byte protocol limit. Applying it is best-effort and propagates coroutine cancellation. | Matches the frozen join helper; actual confirmed channel creation remains owned by WP-310. |

No frozen Swift input was changed or advanced beyond
`db14559b39d32322b06477c6ae676112f583db50`. No permission, billing,
analytics, updater, evidence-retention, reservation, or approval machinery was added.
