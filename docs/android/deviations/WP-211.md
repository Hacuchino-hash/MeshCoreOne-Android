## Operation and event ownership

Each factory result is only the device/settings bundle, not a fake full
RadioSessionContainer. It owns a child of the runtime-provided connection Job,
never the physical session or process repositories. Whole verified operations
are ordered by a separate mutex; callback delivery and synchronous subscriber
registration use independent locks, so the response path never requires that
operation mutex. Caller cancellation cancels its service operation, while the
actual protocol's already-written exchange retains its own drain/correlation
policy. Close clears callbacks, terminates subscriptions and joins children
without stopping or recreating the process store or physical transport.

Device-update callbacks likewise receive the incumbent neutral
`SessionEvent<DeviceDTO>` token wrapper. The actual DTO and save-before-callback
ordering remain; later consumers recheck that token at their UI suspension
boundary. External callbacks run after releasing the persistence-operation
mutex, preserving source actor reentrancy instead of deadlocking a callback
that calls the same service.

The source settings stream remains single-active-subscriber/replacement, not
multicast or conflated state. Each immutable event carries the exact token;
obsolete queued settings UI updates are rejected. This does not discard raw
protocol bytes or ACKs. Registering after terminal close yields a completed
subscription. A replaced subscriber's completion cannot unregister its successor.

The source `setOtherParamsVerified` compares only inverted auto-add, then returns
and publishes the actual full self-info readback. It is not silently upgraded to
verify every telemetry/location/multi-ACK field or to publish desired values.
Source read-default-flood-scope events still report actual readback even when a
subsequent write verification fails.
