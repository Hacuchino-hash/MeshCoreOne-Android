# WP-104 command-packet builders

The pure JVM implementation preserves all **63 public method declarations and
overloads** in the pinned `PacketBuilder.swift`, including its coordinate helper.
This is the command packer, not a connected radio/session implementation.
Reference: `db14559b39d32322b06477c6ae676112f583db50`.

| Source contract | Native implementation and evidence |
| --- | --- |
| Swift `Data` and unsigned wire integers | Existing immutable `Bytes` and `ByteWriter`; explicit `UByte`/`UShort`/`UInt` and signed transmit power, never enum ordinals |
| `Date` seconds, truncation and saturation | `Instant` with seconds clamped to `0..UInt.MAX_VALUE`; fractional seconds truncate, and negative/extreme instants saturate. A non-finite date cannot be represented by `Instant`. |
| Coordinate and radio saturation | Non-finite coordinates encode zero; radio values use the source lower bound. Finite values saturate and radio rounding is half away from zero rather than JVM ties-to-even. |
| Five-character app identifier | Existing extended-grapheme segmentation, not five bytes/code points/UTF-16 units; combining accents, family emoji, flags and CJK execute in tests |
| Fixed-width UTF-8 names | Existing grapheme-safe helpers preserve the 31-byte device-name cap, 32-byte channel/contact field and 30-byte persisted scope name plus terminating padding |
| Public-key fields with differing legacy policies | Preserve prefix-only fields versus the three hardened padded-key queries; short input is not globally normalized or rejected |
| Channel binary datagram packer | Preserve encoded path byte and caller-supplied path bytes, omit path only for flood, LE data type, and independent 163-byte payload clamp. The session must validate firmware capability, path consistency and forbidden types. |
| Raw data, signing and imported keys | Preserve only the source's actual clamps. Signing chunks and imported private-key bytes are not silently truncated or padded. |
| Anonymous request return path | Reverse raw bytes exactly as the source does, not multi-byte hop groups |
| Implicit discovery tag | JCA `SecureRandom` supplies a uniform nonzero 32-bit word; explicit zero remains valid at the low-level builder |
| Auto-add payload input | Admit the actual immutable `DevicePayloads.AutoAddConfig` fragment, including all five bit constants, in canonical `model/AutoAddConfig.kt`. WP-106 reuses this type; no fake event/parser/session is introduced. |

The exact extra canonical model path is recorded in the coordinator's WP-104
write reservation. The manifest's 65 IDs/185 edges, source owners and protected
automation settings are unchanged. Production adapts MIT MeshCore sources only;
no new dependency, version pin, global provider, license or GPL display adapter
is added to the protocol runtime.

## Original cases crossing later components

The original six assigned test files have **96 declarations**. This change ports
their **44 direct builder declarations**, including the three-row path-hash-mode
parameter family. The fourth `UpdateContactTests` declaration's legacy-session
encoder seam is exercised directly, but the original
`changeContactFlags` asynchronous send/acknowledgment scenario still requires
WP-107 and is **not claimed passed**.

The other **51 cross-component declarations** are retained, not excluded:
20 non-builder `V112ProtocolTests` cases require response parsing, events or
contact-manager behavior; 31 non-builder `RoundTripTests` cases require response
parsers or LPP. These continue in WP-103/105/106/107/109 and the final WP-501
parity audit. Headers, the method-surface check and passing builder tests do not
declare those cases, the full WP-104 source-test-parity acceptance, or the app
feature-complete.
