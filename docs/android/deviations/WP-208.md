# WP-208 native messaging adaptations

Pinned source: `db14559b39d32322b06477c6ae676112f583db50`.
Manual receipt: `autonomous-WP-208-7e2835ba`; exact identity and admitted
shared paths are recorded in `docs/android/evidence/WP-208/receipt.json`.
These adaptations are candidate behavior, not self-approved parity or gates.

| Source concern | Native behavior and consequence |
| --- | --- |
| Actors are reentrant while awaiting; queues own separate tasks. | Short state locks protect snapshots and full-operation mutexes protect DM/channel work. ACK callbacks use a different mutation lock, never the send mutex they must unblock. Parent-owned generation scopes, clocks and jitter are injected. |
| A per-connection container owns message monitoring, ACK expiry and drains. | Services receive only neutral connection signals and actual protocol/persistence roles, plus resolved radio/public-key identity. They never import `ConnectionManager`, close the process store or own the physical transport. WP-303 still assembles the graph. |
| Source event broadcaster closes multicast streams. | Eager, unbounded per-subscriber queues preserve every status event, including equal events, and explicitly complete/fail present and later subscribers. Events carry the process epoch/generation/radio token. No ACK StateFlow, competing receiveAsFlow or lossy messaging buffer is added. |
| Source precomputes ACK before send; firmware may return another code. | Both persistent tracking and attempt-local protocol collection register before send. Predicted and authoritative codes accumulate; earlier-attempt/attempt4 ACKs resolve the same logical message. Firmware RTT is retained, never synthesized from dates. |
| ACK CRC does not include the recipient; source only warns about cross-message collisions. | An ambiguous collision between distinct live messages is diagnosed and rejected before another wire send. It cannot deliver the wrong target. Full source hash bytes, two-bit attempt mask and timestamp remain unchanged. |
| Retry configuration has five attempts, four before reset, one flood. | Actual raw command/attempt counts are asserted. The two source-unused booleans remain values only; this port does not silently activate path-discovery or change their semantics. Retry exhaustion stays sent through max(give-up window, last ACK timeout), rather than following stale guide diagrams that imply immediate failure. |
| Source best-effort/try? bookkeeping can emit a status without a corresponding row transition. | Typed persistence causes are reported and unresolved causes survive teardown. Failed/absent/otherwise terminal rows cannot emit fake delivery or sent updates. Confirmed on-air sends are not described as rolled back. |
| Queue success cleanup may fail after the radio accepted a send. | Generation-local receipts retry bookkeeping/deletion/indexing without a second accepted send in that generation. Across cold restart, the persisted attempt count preserves the original wire timestamp; no unsupported exactly-once physical-radio claim is made. |
| Ready edges wake parked source queues, but source hydration can attempt work before that edge. | Native hydration can occur before the runtime publishes its token. It loads process persistence once/coalesced but gates wire work and attempt bumps at matching ready, not physical connected/syncing. |
| Hydration/read faults can be swallowed or permanently latch a failed hydration. | Missing rows are distinct from thrown reads. Failures are typed, rows remain authoritative, and retrying hydration cannot duplicate already claimed envelopes. |
| Polling/manual drain and session auto-fetch both observe the same protocol results. | One authoritative generation-owned drain is coalesced across observers. Cancelling one observer does not cancel it. Paired raw-event echo accounting prevents duplicate handler calls; each backlog drain has one fresh anchor. |
| Source lookup failure is treated as an unknown sender/channel via try?. | A failed lookup/handler remains an explicit failure with its consumed message retained for retry/teardown. Genuine absent rows still route with null metadata. Cleared/unwired handlers cannot produce successful polling. |
| Channel NOT_FOUND has both pool and deleted-slot meanings. | Source thresholds, bounded wait, full pool backoff, authoritative injected query and per-message consecutive-failure caps are retained. No WP-209 service is fabricated. Outgoing reaction indexing is an injected role, using the actual post-resend timestamp; no WP-216 implementation is added. |
| Dedup is shared by messaging, orphan adoption and backups. | A source-backed pure model helper reuses the existing protocol SHA-256/immutable bytes/UUID helpers. Only the admitted RepositoryDeduplicationKey object delegates to it; every other repository-policy line is unchanged. UTF-8 hash input is not NFC-normalized. Existing incoming-nil-only export backfill, outgoing UUID identity, empty keys and valid explicit sort dates are preserved. |
| Two original queue cases are disabled due to harness/time limitations. | Both are enabled deterministic native assertions through actual protocol transport and virtual30-second timing. No original family is excluded or skipped. |

## Independent immutable-head review repair delta

The coordinator's completed read-only review of `8bbad096d903b8789b47a4bdbe5ed563cfb83783`
identified five high and three medium defects. The same WP/PR repairs below retain
the frozen reference, all128 original families/131 expanded identities and both

| Finding | Candidate repair / actual assertion surface |
| --- | --- |
| HIGH1 persisted-message callback deadlocks on the wire mutex or closes its own deferred | Persistence completes in an owned save operation before the external callback runs in caller context, outside the DM wire lease and active send job. Real-session nested-DM and close callbacks plus an actual Room close callback are bounded and assert one persisted notification. |
| HIGH2 accepted insertion outlives shutdown/successor hydration | Queue acceptance and closing share one atomic claim. An explicitly queue-owned durable-submission scope retains accepted LAZY writes independently of observer/radio cancellation. Shutdown joins authoritative completion before returning, retaining committed rows and actual failure causes. Actual Room tests block an unstarted/accepted insert, cancel its observer, order shutdown before successor hydration, and retain a real closed-store failure. |
| HIGH3 ACK in retry-status/flood suspension still resends | A logical claim keeps ACK completion after correlation-table removal. Every suspended retry transition and the last pre-wire/backoff boundary rechecks that completion. Real ACKs during blocked status/reset work assert no second attempt; the Room status writer uses the actual terminal-safe transaction. The frozen Swift await gap is documented, not edited or used to justify duplicate delivery. |
| HIGH4 successful manual resend is retransmitted/recounted after final-read failure | A persisted PendingSend row ID identifies the manual claim. Accepted wire result, confirmed ACK, timestamp, count commit and resend publication survive reconciliation failure until pending-row deletion finishes. A new row/new Send Again claim remains distinct. Real-session and actual Room true-ACK/final-read-only faults assert counts1->2, wake without another packet/count, then a genuine new claim to3. |
| HIGH5 residual shared-poll result is retained but never delivered | Manual echo accounting preserves an ordered event deque. Unpaired results move to generation-owned dispatch and are fully handled before successful manual completion/ownership release; failed handlers retain the original record/cause. The actual session's preexisting shared getMessage completes during an observed stop barrier, followed by manual NoMore; its consumer must run once before completion. |
| MEDIUM6 manual pause/resume overwrites newer user intent | Desired enabled/paused state and revision are separate from actual auto-fetch activity and the atomic accepted manual claim. Control reconciliation cannot start auto consumption while manual owns the drain and evaluates current intent on release, not an old resume boolean. Real-session controls/competing observers assert pause preservation and delayed newest resume. |
| MEDIUM7 RX completed keys use raw Kotlin string inequality | Only completed-key comparison normalizes both keys to NFC, matching source canonical equality. Raw content remains unnormalized before SHA-256 and in DTOs. Composed/decomposed sender aliases match; different raw Unicode body hashes do not. |
| MEDIUM8 any valid-shaped base SHA is accepted | Evidence requires the exact authorized base `7e2835bad2c03dfb5a088063655f9fc4dbafd00f`, captured head/source/manifest/policy/run/attempt. A later base requires a new trusted coordination/merged-ancestor receipt, not a shape-only override. Different valid40-byte base and positive-but-different run/attempt regressions fail closed. |
