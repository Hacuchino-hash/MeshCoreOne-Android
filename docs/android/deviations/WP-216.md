## A-01: shared shape

Actor state becomes lock-confined state that is never held across a suspension.
`ReactionService`'s cache operations (`index`, `queue`, `find`, `clear`) are plain
calls, and its store-backed operations suspend. Neither service launches
coroutines, so no scope is injected. `ReactionService` takes a `Clock` for
`receivedAt` and the cache's `indexedAt`. Logging uses `java.util.logging`
(`PersistentLogger` belongs to WP-212).

- **Store keys:** the Android store keys rows by radio. The RX-entry duplicate
  check uses the configured radio, repeats are saved and looked up under the
  message's own radio, and `refreshRepeats` takes an `EntityKey`.
- **Types:** Swift `Int` maps to `Long`, `UInt8`/`UInt32` map to `UByte`/`UInt`,
  and radio `UUID` maps to `RadioId`. The summary tuple is a `ReactionCount` data
  class.
- **Events:** a local broadcaster replaces `core:runtime`'s `EventBroadcaster`,
  which `core:services` can't depend on. Registration is synchronous, as in
  Swift. Each `events()` stream must be collected exactly once, and a second
  collection throws `IllegalStateException` instead of silently yielding
  nothing.
- **Same-instant tie-break:** when two cache candidates share an `indexedAt`,
  the most recently indexed one wins. Swift's `max(by:)` keeps the first, which
  only differs when two indexes read the same clock instant. Android's clock
  makes that plausible within a sync batch.
- **Privacy:** an unparseable channel text is logged at FINE with its length
  only, never its decrypted content.

## A-02: text semantics

Expected values were printed by the frozen Swift sources compiled with the local
toolchain (`ReactionsSwiftOracleVectors`).

- **Equality:** `ParsedReaction` and `ParsedDMReaction` compare strings exactly,
  where Swift compares by canonical equivalence. Pending-queue and cache keys use
  canonical sender names.
- **Summary order:** groups tied on count and earliest time keep first-appearance
  order. Swift leaves that to dictionary hashing. Canonically equivalent emoji
  group together, as in Swift.
- **Unpaired surrogates:** Kotlin strings can hold them, and they encode as `?`
  in the UTF-8 hash. Swift strings can't contain them.
- **Grapheme gap (pinned by a test):** for adversarial input such as
  `"@[A]👍‍‍👍\nabcdefgh"`, the JDK grapheme matcher sees one cluster
  and the parse succeeds, where Swift sees two Characters and returns nil.
  WP-213's `ReactionWireFormat` behaves the same way. Android's ICU-backed `\X`
  is unverified on-device.

## Test adaptations

- **Fakes instead of SwiftData:** the in-memory store is a fake with fault
  injection.
- **No sleeps:** Swift's 10 ms sleep becomes a ticking clock.
- **Store-only case:** "exact text disambiguates messages sharing channel and
  timestamp" only exercises the fake store's `findSentChannelMessage`. It needs a
  Room-backed assertion in WP-202.
- **Four test files:** the 22 `HeardRepeatsServiceTests` ids are 8 parse cases,
  5 sent-echo cases and 9 extra-path/harvest cases. The `ChannelRXCorrelation`
  checks are extra native cases.
