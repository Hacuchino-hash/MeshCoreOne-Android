# WP-304 native shared-component adaptations

Source specification: `db14559b39d32322b06477c6ae676112f583db50`.
Lease: `autonomous-WP-304-824df06b`. This is a bounded shared-UI library, not
app-graph/navigation integration, a complete app or a source-parity acceptance.
All 88 primary inputs, 130 original families and 158 parameter scenarios remain
accounted for; unavailable producer bindings are blockers, not exclusions.

## Native presentation

SwiftUI alert/sheet/menu/Liquid Glass APIs become Material dialogs, menus and
surfaces. No SF Symbol artwork, Apple blur skin, new brand/theme, dynamic color,
paid feature, account, analytics, updater, permission or background service is
introduced. Existing ten-theme palettes, identity/category algorithms, licensed
Mesh icons and generated twelve-language resource accessors are consumed.

Controls use the incumbent native 49 dp minimum, exceeding the 48 dp requirement.
Text wraps and follows font scaling rather than using source fixed-height or
Dynamic Type caps. Avatar containers scale with the font setting so initials
remain unclipped. Native foreground roles may fit contrast without changing
source palette/identity fills. Disabled deletion rows retain legible text and
pass disabled state to their child controls instead of dimming primary text.

One shared safe-drawing/IME inset union is consumed by its layout. Dialogs use
native dismissal/Back/focus. Error retry clears the occurrence before invoking
the injected action; passive errors remain until dismissed. Error/progress,
headings and selected states have textual/semantic alternatives. No whole-chat
live region or physical TalkBack claim is made.

The shared scaffold paints the current Material canvas and supplies its matching
content foreground; a dark component cannot sit on an unrelated native light
window background. Native dialog font/direction evidence configures the actual
Android resource state and checks TextLayoutResult density/direction, not merely
a parent composition-local override or a screenshot filename.

The native cropper keeps 1...4 scale, 0.25 zoom steps, 32 dp guide margins,
300/480 dp caps, 1024-pixel decode cap and actual 512-square output. The
platform image decoder applies EXIF orientation; decoded images are supplied
outside composition through an explicitly injected bounded cache. Decode IO
failure is typed/reported and the source initial-avatar fallback remains.

## State, ordering and actions

Content takes immutable snapshots and action callbacks. Composition does not
construct storage/radio/app graphs or perform connect/send/import/GPS/network
operations. Initial expanded-section load admission is an explicit screen-owner
entry action, not a recomposition effect. Leaving a component does not close the
process preference store or the radio connection.

RSSI keeps signed Swift-width Long values, -60/-80 thresholds, three-dBm
hysteresis, 0.2 newest weight, two-second expiry cadence and strict older-than-
four-second expiry. Scan identity is generic caller-owned pairing identity, not
a generated radio UUID. Name retention, lossless ordered consumption and
structured cancellation are preserved; unusable readings alone are skipped.

Region validation keeps the source whitespace-only trim, ASCII letters/digits/
hyphen rule, exact duplicate matching and 30-byte limit. ICU supplies native
localized standard/numeric sorting and substring comparison. Discovery payload
selection is emitted in displayed sorted order; the source Set-to-Array order
was not specified. This deterministic native ordering needs reviewer acceptance.
WiFi host/port grammar, comma replacement, focus Next/Done and raw input remain
source-based. No LAN permission is requested by these components.

Whitespace trimming is specifically Unicode Zs plus tab, not line/paragraph
separators. Empty region input remains invalid without fabricated error copy.
Numeric tertiary collation gives deterministic case/diacritic ordering; primary
collation is used only for source case/diacritic-insensitive search. Equal
collation values have a deterministic text tie-break. Dialog focus is requested
inside its attached text-field composition, and native menus dismiss before
dispatching the selected callback.

Sorting and substring search use separate collators. ICU does not support
StringSearch with numeric collation, so only sorting enables numeric behavior.
Substring search remains primary/case/diacritic-insensitive and functional.

Native ICU formatting replaces Apple date formatters with injected clock/zone/
locale. The exact under-60-second and seven-day boundaries and wire Unix seconds
remain; minute effects are keyed and cancellable. ICU glyph segmentation is an
explicit SDK31/37 adaptation, not a claim that every Unicode-version edge is
identical to Swift on all platforms.

Relative-date copy uses numeric integral components. Conversation previous-day
copy separately uses named relative components rather than labeling every
previous-calendar-day time "yesterday"; same-day time honors the actual Android
12/24-hour setting. Fixed-offset zones are converted to supported GMT-offset
IDs before ICU formatting. Locale changes invalidate both timestamp contents.
Foundation rounding/calendar oracle evidence remains unverified.

## Real show-once persistence

`ShowOnceTips` receives the merged process-owned `PreferenceStore`; it has no
in-memory production backend and no close/storage factory. Original
`DeviceMenuTip`/`LiveActivityTip` IDs and `hasCompletedOnboarding`/`radioConnected`
event IDs survive in native-owned keys. Event eligibility and the displayed flag
are probed/set in one serialized DataStore update. Separate consumers/reopen/
radio switching cannot produce a second durable claim. Type/IO/lifetime failures
and cancellation propagate rather than creating false defaults.

The claim is persisted before UI display, giving at-most-once presentation.
Cancellation/process loss after the claim may consume an unseen nonessential
tip rather than repeatedly interrupt a task; this consequence is explicit and
requires review. A busy task or another overlay does not claim a tip. Live-status
copy is eligible only when the caller actually presents the native status
surface; it neither grants notification permission nor qualifies an ambient
radio for promoted Live Updates.
